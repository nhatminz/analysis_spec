# Policy-lag v5: stale / fresh / Reflex

Only fastgrpo code is changed. Reflex was ported from the production sibling
SpecNaacl revision recorded in `helper/reflex_port.json`; there are no runtime
Python imports from that repository. The sibling is used only for pretrained
checkpoint/config/vocabulary files. No models are downloaded.

## Protocol

At target update boundary t, stale and fresh start from identical phi_base and
AdamW state. Stale learns from R_t/theta_t; fresh supervision is collected with
theta_(t+1) and phi_base on the same source prompts. Each branch uses one
optimizer step, draft LR 1e-5 and the same number of valid supervision positions:
min(8192, stale_available, fresh_available). Requested and actual budgets are
logged. Target packing remains 1024; target LR remains 1e-6.

On the next real eight-prompt GRPO batch, all three branches use theta_(t+1),
eight responses per prompt and the same captured initial RNG:

| Branch | Persistent draft | Reflex | Used for target update |
| --- | --- | --- | --- |
| stale | phi_stale | OFF | yes |
| fresh | phi_fresh | OFF | no |
| reflex | phi_stale | ACTIVE | no |

Fresh and Reflex are shadows. Persistent target/draft/optimizer/GRPO-buffer
identities are checked. Phi_stale, model modes and captured RNG are restored
before the real stale rollout. Reflex A starts at zero per response per rollout,
is not an nn.Parameter or optimizer state, and is cleared after the rollout.
Bootstrap resamples paired prompts, retaining all their responses together,
for both fresh-minus-stale and reflex-minus-stale.

Reflex defaults are triton/root/fused/serial/serial/auto, CUDA update stream on,
feature_dim=8, LR=0.05, weight_decay=0.0. Feedback reuses the existing target
verification distribution. There is no extra target forward for Reflex and no
per-round device synchronization when STATISTICAL_TIME=false (the default).
The regular teacher-shift diagnostic/supervision collection still needs its
own target forwards; these are distinct from Reflex feedback.

EAGLE-3 auxiliary features are unchanged. Decoder tokens are already shifted
once; only final teacher hidden and the supervision mask are aligned with
SpecForge TargetHead.preprocess. Prompt/padding/last-token validity is retained.
GRPO sequences, masks, advantages and response identities use one permutation.

## Schedule, resume, and retention

Defaults ANALYSIS_BOUNDARIES=1, ANALYSIS_INTERVAL=5, TOTAL_POLICY_STEPS=600 give
120 boundaries: 1,5,10,...595, never 600. The step limit is **absolute target
optimizer steps**, including on resume, not 600 additional steps.
NUM_EPOCHS=2 is a minimum; the iterator extends if necessary to reach the step
limit. A complete epoch with no usable target update fails with a diagnostic.
DataLoader has a separate seed-plus-epoch generator, so resume reconstructs
the consumed epoch permutation without advancing rollout RNG.
Training checkpoints also preserve Python, NumPy, Torch and CUDA RNG states;
the default resume restores all four, not just the Torch generators.

Use a new OUTPUT_DIR for v5. Protocol/source/config hashes reject old v4 or
changed experiment configurations. Resume with the same OUTPUT_DIR, immutable
original draft assets and RESUME=true ANALYSIS_RESUME=true.

For the B200 run that reached target step 59 before a process-level `Killed`,
the memory maintenance patch recognizes only its recorded v5
`grpo_speculative.py` SHA-256. All model/data/config fields and other source
hashes must still match. The original and updated source hashes are retained
in `analysis/memory_maintenance.json`. The patch captures full draft/AdamW,
LoRA and teacher snapshots only on batches that can reach an analysis boundary;
pending evaluation retains just its stale draft snapshot and target identity.
After ordinary online draft training, rollout supervision tensors are released
before GRPO target backward unless the current batch reaches a boundary.
Checkpoint `latest.pt` is published from the already serialized step file,
using an atomic hard link or streaming-copy fallback. Each saved target step
records process RSS, cgroup memory and CUDA allocation in `logs/train.jsonl`
as `phase=resource_after_checkpoint`. A bare `Killed` message does not by
itself establish whether memory pressure or an external job limit sent SIGKILL.

Pending boundaries keep draft_stale.pt (including its optimizer for retries)
and draft_fresh.pt. Phi_base.pt is needed only for optional debug retention.
Temporary branch files are removed only after the following GRPO training
checkpoint is atomically saved and results are marked durable. Set
ANALYSIS_KEEP_BRANCH_CHECKPOINTS=1 to retain all three branch snapshots.
Deleted temporary weights can be regenerated by replaying training, not
recovered from scalar result files. Regular latest training checkpoints remain.

Small atomic per-boundary results.json journals preserve all raw response
counters and summaries. Global CSV/JSONL files append new boundary rows; they
are rebuilt once on startup/end (or --mode plot) to reconcile a crash during
append. An undurable boundary is not included in --mode plot.

## Timing and outputs

`stale_online_draft_update_gpu_ms` brackets the equal-budget draft forward,
backward and AdamW update with CUDA events. Fresh is measured similarly.
`reflex_update_gpu_ms` sums CUDA event intervals around actual feedback/A
updates only, on the update stream, excluding target forward and proposal
computation. Events are materialized after the rollout, not after each update.
Event intervals can include launch/host gaps; they are not profiler kernel-only
durations. `reflex_update_count` counts **trajectory updates**, as in production
ReflexStats.updates, not batched kernel launches. The per-update value divides
total feedback GPU ms by this count.

With the update stream on, `reflex_update_exposed_ms` sums positive event-time
gaps between update completion and main-stream readiness immediately before
the dependency on new A. It measures the exposed stream dependency; it is not
added to the total compute time. With streaming off the exposed value is null.

`analysis_io_wall_ms` records CPU serialization/file/checkpoint-write overhead;
GPU-to-CPU snapshot materialization happens outside the IO timer. Boundary
rows include branch snapshots and result export; final aggregation refreshes
the final timing scalar from io_timing.json. Its own tiny write is excluded to
avoid self-referential timing. Run logs/summary also count housekeeping and
aggregation IO. `corrected_wall_time_s = total_wall_time_s - analysis_io_wall_ms/1000`
subtracts only IO, never actual GPU work or correctness synchronization. It
still includes shadow evaluation and adaptation computation, not a standalone
training-throughput benchmark. Rendering happens after training wall timing.

Results: analysis/step_metrics.csv, step_metrics.jsonl, per_response.jsonl,
summary.csv, summary.jsonl, boundaries/step_*/results.json, and the end-of-run
aal_policy_lag.png. AAL is always sum(accepted_length_sum)/sum(verification_rounds),
including the root/bonus target token, not arithmetic mean of response AALs.

## B200 command

After deploying the entire updated fastgrpo folder (including the new helper
files), use the existing B200 environment with the pinned SpecForge/torch stack:

```bash
cd /workspace/storage-shared/nlp/minhpn19/fastgrpo

SPECNAACL_DIR=/workspace/storage-shared/nlp/minhpn19/SpecNaacl
SPLIT_DIR=/workspace/storage-shared/nlp/minhpn19/outputs/fastgrpo/policy_lag/dapo_math_seed42
OUTPUT_DIR="/workspace/storage-shared/nlp/minhpn19/outputs/fastgrpo/policy_lag/qwen2_5_3b_instruct/reflex_v5_$(date -u +%Y%m%dT%H%M%S)"

SPECNAACL_DIR="$SPECNAACL_DIR" \
TARGET_MODEL_PATH=/workspace/storage-shared/models/Qwen2.5-3B-Instruct \
DRAFT_CHECKPOINT="$SPECNAACL_DIR/outputs/pretrain/qwen25_3b/latest_checkpoint" \
DRAFT_CONFIG="$SPECNAACL_DIR/outputs/pretrain/qwen25_3b/latest_draft_config.json" \
VOCAB_MAPPING="$SPECNAACL_DIR/outputs/pretrain/qwen25_3b/latest_vocab_mapping.pt" \
TRAIN_DATASET_PATH="$SPLIT_DIR/train.jsonl" \
EVAL_DATASET_PATH="$SPLIT_DIR/eval.jsonl" \
OUTPUT_DIR="$OUTPUT_DIR" \
ANALYSIS_BOUNDARIES=1 ANALYSIS_INTERVAL=5 TOTAL_POLICY_STEPS=600 \
NUM_EPOCHS=2 TRAIN_BATCH_SIZE=8 ANALYSIS_EVAL_PROMPTS=8 EVAL_BATCH_SIZE=8 \
RESPONSES_PER_PROMPT=8 TRACE_SEED=42 \
DRAFT_TOKEN_BUDGET=8192 DRAFT_UPDATE_STEPS=1 DRAFT_LR=1e-5 \
TARGET_MAX_TRAINING_TOKEN=1024 TARGET_LR=1e-6 \
REFLEX_BACKEND=triton REFLEX_FEEDBACK_SCOPE=root REFLEX_UPDATE_STREAM=1 \
ANALYSIS_KEEP_BRANCH_CHECKPOINTS=0 RESUME=false ANALYSIS_RESUME=false \
CUDA_VISIBLE_DEVICES=1 PYTHON_BIN="$(command -v python)" \
bash run_policy_lag_analysis_b200.sh
```

Pretrained latest symlinks are resolved once before starting the experiment.
To let the B200 launcher prepare/reuse the existing DAPO split from parquet,
omit both TRAIN_DATASET_PATH and EVAL_DATASET_PATH (never just one).

Plot/reaggregate completed results later without loading a model:

```bash
python policy_lag_analysis.py --mode plot --output-dir "$OUTPUT_DIR/analysis"
```

Local verification:

```bash
cd fastgrpo
PYTHONPATH=.:third_party/SpecForge python -m unittest discover -s tests -v
python -m py_compile grpo_speculative.py policy_lag_analysis.py helper/*.py tests/*.py
bash -n run_policy_lag_analysis.sh run_policy_lag_analysis_b200.sh
```

The CUDA test uses a tiny synthetic model, not pretrained EAGLE-3 weights or a
full GPU experiment. CPU smoke is explicitly tagged research_result=false.
